# P010 · 日志统一（系统唯一时间线）

## 范围
把「日志」做成系统里唯一的时间线概念：请求、错误、后台执行（原称「任务」）的
生命周期与内部事件全部汇入同一条日志流，任务不再作为用户可见的独立概念存在；
同时开放日志的 Agent 查询面（MCP logs 域），并以同一口径重建前端日志页。

## 权威
- 用户口述（2026-10-03）：「日志不应该是系统里所有发生的事情都在这里面吗？
  要么它怎么叫日志呢？你把任务给我去掉，我们现在只有一个东西叫日志。」
- 诊断事实：logs 表 48 万行中与任务相关的仅 55 行；任务事件另存 job_events；
  前端把「后台任务」当与日志并列的第二区块呈现 → 用户视角出现两个概念。

## 关键决策
- **任务不再是概念，但保留调度索引**：jobs 表带状态机（pending→running→终态）+ 重试 +
  并发锁 + 幂等键，是异步系统（蒸馏/wiki 生成/索引重建）的发动机，也是「重跑」按钮的底座。
  它保留为**日志的投影**（内部调度面），不再作为与日志并列的用户概念。
- **job_events 并入 logs**：迁移 0067 建 job_id 表达式索引 + 历史回填；job_events 表
  按「迁移只增不改」纪律留表停写（同 P008 的 wiki_review_items 处理法）。
- **用户可见概念只有「日志」**：前端/MCP/HTTP 三面「任务」措辞清零。
