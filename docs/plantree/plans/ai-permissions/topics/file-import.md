# 文件批量导入为会话

`session-write` 的批量版：上传文件 → 自动解析成会话 turns → 走蒸馏。解决"逐条 --turn 太麻烦"，同时是"微信等历史数据继承"的通用入口。

## 价值

- AI 继承历史数据（微信导出、旧聊天记录）时，不再逐条 session-write，也不再用 atom-add 直写（断溯源）
- 通用：任何对话记录/历史都能整理成文件喂进来，比"微信专用通道"更简洁

## 格式

| 格式 | 说明 | 优先级 |
|---|---|---|
| JSONL | 每行 `{role, content}` | 首选（结构化，无歧义） |
| 纯文本 | 分段成 turns（按空行/前缀分段） | 次选 |

## 解析与蒸馏

1. 上传文件 → 解析成 turns → 落成一个 session（source 标记为 import）
2. 触发 distill（同 session-write，distill=auto）
3. 产物 source_refs 指向导入会话（溯源完整）

## 边界（"别人的话"）

文件可能含对方内容（微信场景），需结合 **import 模式**：只抽"用户事实 + 人脉关系"，忽略对方观点/内容，避免污染画像。

复用点：分段（6000 字符）+ LLM 调用 + 实体/关系/原子落库；差异点：prompt 收紧为"只抽用户本人事实 + 人脉"。

## 防爆

- 文件大小上限（超限拒绝或分批）
- 分批走现有 job 队列后台跑
