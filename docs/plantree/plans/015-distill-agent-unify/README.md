# P015 · 蒸馏链全面 Agent 化（仲裁 Agent 化 + embedding 退役评估）

> 2026-10-04 用户拍板登记。状态：**planning**（方向已定，分阶段与代价确认待过会）

## 用户设想（原话转写）

L0→L1 分两个模型：**决策模型**（JEV，判断值不值得记）+ **维护模型**（Agent）。
维护 Agent 给 4 个工具——**查 / 入库 / 修改 / 删除**——新原子进来它自己查相似、自己判断
new/duplicate/contradicts、自己决定入库还是修改还是丢弃。关掉 think 思考链，用强提示词约束。
**这样全程不需要 embedding 模型。**

## 评估结论（2026-10-04 实查）

### 成立的部分

1. **与 P012 同构**：组织阶段已 agentic 化（六工具循环），仲裁跟上 = 蒸馏链形态统一
2. **栈简化真实**：可退役的向量基建 = pgvector 列与索引 / refresh_embeddings_by_ids /
   reembed_memory 任务 / llm_providers embedding 行 / 混合检索向量腿 / 缺向量横幅
3. **现有仲裁的两段式确实别扭**：向量 ANN 召回相似 → 有相似才 LLM 精判、无相似直接转正——
   向量召回质量直接钳制判定质量（T002 verdict 校验坑、archived 无向量跳过检测的坑都在这层）
4. **think 可关**：判新/重复/矛盾是细粒度分类任务，MiniMax-M3 关思考链 + 强提示词 + JSON 输出可行

### 必须知情的代价（拍板前读完）

1. **检索语义腿消失（最大代价）**：混合检索 = 向量路 + 全文路 RRF。embedding 退役后检索
   退化为纯 FTS（jieba 字面命中）——「意思近但说法不同」的记忆将搜不到。开场装载画像、
   按语义找记忆的能力直接降级。**缓解选项**：检索查询由 chat 模型生成变体（成本+延迟）/
   接受纯 FTS（专有名词召回不差，同义改写弱）/ 检索保留向量只仲裁去
2. **查全率风险**：Agent 的「查」以新原子文本构造查询词走 tsv——字面不命中的语义重复
   （「我喜欢周杰伦」vs「常听周董的歌」）会漏 → 重复原子入库。缓解：Agent 多轮换词查 +
   查询变体生成；但需要评测对照（P012 评测框架可复用）
3. **每候选成本上升**：现状无相似直接转正（0 次 LLM 调用）；agentic 化后每候选至少 1 次循环
   调用（查）+ 判定轮。MiniMax 便宜，但重蒸几百候选要量化

### 分阶段建议（待拍板）

- **阶段一：仲裁 Agent 化**（收益大、风险可控）——四工具 Agent 替代「ANN 召回 + LLM 精判」，
  检索向量先保留。评测对照新旧仲裁的重复检出率/误杀率
- **阶段二：检索向量去留**——评测纯 FTS 召回质量 vs 混合检索，数据说话再定
- **阶段三：向量基建退役**——列/索引/重嵌任务/横幅，随前两阶段结论执行
