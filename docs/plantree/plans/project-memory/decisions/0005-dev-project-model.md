# 0005 开发项目详情模型：位置数组 + 分类>文档树，类型=分类模板

**日期**：2026-09-04　**状态**：已拍板

## 背景

用户给出开发项目详情页的具体画面（Wiki 式左树右内容），本轮对齐了四个关键分叉：主机登记制、云端为主、双入口平等、plan-tree 消融（0004）。

## 决策

### 三表模型（核心结构）

| 表 | 职责 | 要点 |
|---|---|---|
| `projects` | 项目本体 | name / type（dev·research）/ status（进行中·暂停·完成·放弃）|
| `project_locations` | 位置数组 | `{主机, 路径, 用途}` 多行，**登记制**（纯元数据，不远程读取）|
| `project_docs` | 文档 | `分类 + markdown 内容 + 轻结构元数据` |

### 关键约定

1. **类型 = 预设的分类模板**：开发预设「后端/前端/测试/规划」，调研预设「待查/线索/资料/结论/疑点/证伪」；两类共用「分类 > 文档」同一结构。
2. **分类可增删**：类型只给初始分类，建后每个项目自由增删改（如加「运维」「设计」）。
3. **md + 轻结构**：文档正文纯 markdown，带少量元数据（状态标签如 进行中/已完成 等，字段集设计时定）。
4. **云端为主**：文档内容以 agent-memory 库为准。AI 拿到新项目 → 检测本地文档 → 登记导入云端 → 之后维护在云端（本地文件降为次要快照）。新项目直接记云端。
5. **双入口平等**：Web 表单与 AI（memory.py）都是一等入口，都能建项目/改文档/管分类。
6. **项目管理层**：列表页支持新建/编辑/**多选批量删除**/类型区分筛选。

### 展示（Web）

Wiki 式左树右内容：左树 = 位置 + 分类（带文档计数）；右侧 = markdown 渲染/编辑。

## 后果

- 「分类 > 文档」是跨类型统一结构，调研类型零额外建模成本。
- AI 跨会话接续 = 拉项目 context pack（规划分类下路线图 + 关键文档）。
- 与 knowledge 域的关系（检索管线是否打通）留 open-question。
