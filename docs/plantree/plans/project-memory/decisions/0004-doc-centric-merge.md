# 0004 plan-tree 概念消融为「规划」文档分类（修正 0003 的迁入形态）

**日期**：2026-09-04　**状态**：已拍板

## 背景

0003 决定 plan-tree 能力「整体迁入、概念结构化为一等公民」。本轮开发项目详情设计时用户澄清了真实意图：**不要 plan-tree 作为独立概念出现在系统里**——「它应该跟我们的所有文档已经深入融合了，之后我的项目里就不会有 plan 这个东西了，只会有我们这个系统」。

## 决策（修正 0003 的形态部分）

- **概念消融**：项目域里没有「plan tree」名字、没有独立区块。规划/路线图/决策记录 = 项目文档的一个**分类**（「规划」），与后端/前端/测试文档平级，同一棵「分类 > 文档」树。
- **迁移语义不变**：docs/plantree/ 的内容仍可导入，落点为「规划」分类下的 markdown 文档；plan-tree skill 仍退役。
- **0003 的「一等公民结构化」硬约束作废**——不需要 roadmap/decisions/evidence 各自的结构化表；跨会话接续靠 AI 读规划文档内容，不靠结构化字段。

## 保留不变的

- 迁入方向不变（plan-tree → agent-memory 项目域，单一载体）。
- markdown 可导入不变（plan-tree 结构规整，导入器按「文件 → 文档」映射）。

## 后果

- 数据模型大幅简化：不需要为 plan-tree 概念建表；见 [0005](0005-dev-project-model.md) 的三表模型。
- 0003 中「概念 → 身份」的映射表仅作历史推理记录，不再约束设计。
