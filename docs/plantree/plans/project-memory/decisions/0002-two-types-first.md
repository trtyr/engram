# 0002 类型先行「开发 + 调研」两种；类型决定骨架；学习归 learnsys

**日期**：2026-09-04　**状态**：已拍板

## 背景

项目不一定是开发项目（搜索类、调研类等），不同类型项目的内部组织结构不同——用户明确「这个一定要分类」。候选类型曾列出开发 / 调研 / 学习三种。

## 决策

1. **类型先行两种：开发（dev）+ 调研（research）**。
2. **类型决定三样东西**：① 分区骨架（格子怎么切）② 每格内容形态（bug 记什么、结论记什么）③ 流转状态（什么算完）。
3. **学习类不做**——归 learnsys（已有卡片/复习/路径骨架）。
4. **类型系统留扩展位**（未来装修/旅行等自定义类型的可能性不封死）。

## 两类型的骨架草案（对齐时的画面，具体以设计为准）

- **开发**：工程视角。roadmap/decisions/evidence/status（吸收 plan-tree，见 [0003](0003-plan-tree-merge.md)）+ 工单/前端/后端/测试/bug 分区；bug 格内容形态 = 现象+复现+原因+修法，流转 = 开放→修复→回归验证。
- **调研**：探索视角。待查问题 / 线索 / 资料 / 结论 / 剩余疑点 / 证伪记录（查过此路不通的，避免重复查）；无 bug 无测试。

## 后果

- 数据模型需支持「类型 → 骨架」的映射（内置两套 + 扩展位）。
- learnsys 不动；调研类型上线后，搜索类工作流（收网页→沉淀结论）有了归宿。
