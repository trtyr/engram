## 设计特异性判定

**判定：任意 AI 控制台皆可通用。** 侧边栏 + PageHeader + Card + 表格 = shadcn 默认皮肤 + 一个品牌蓝。量化证据：

| 页面 | 平均饱和度 | 彩色像素占比 | 主体色相 |
|---|---|---|---|
| **登录页** | **0.063** | **14.6%** | 210° 蓝（品牌时刻） |
| Dashboard | 0.005 | 0.9% | 210° |
| Memory / Wiki / CodeGraph / Settings | 0.003 | **0.6%** | 210° |
| Wiki 图谱页 | 0.005 | 0.8% | 210° |

**登录页承诺了一个有品牌的世界，进去之后是灰度荒原。** 没有任何与「记忆 / 蒸馏 / 图谱」相关的视觉语言；产品叙事为零。这就是「没有设计感」的数学表达。

## 七维详评

### 1. 布局
- **[P1]** 每页=单列表格堆叠，「Excel 应用」气质；Dashboard 有天然适合可视化的数据（LLM 用量、任务流）却零图表（02-dashboard）
- **[P2]** 详情/事件时间线用「表格下方插入 Card」展开，页面跳动、无过渡；应抽屉/模态/侧滑（03-memory、13-jobs-events 源码 `setOpen` 内联展开）
- **[P1·技术]** 前端路由 `/jobs` 与后端 API 同路径：**硬刷新/书签直达返回裸 JSON 401**（实测复现：`<pre>{"error":...}</pre>`）；其余 7 路由靠 SPA 兜底侥幸不撞
- **[P3]** 会话详情的「擦除」按钮与 ID 同行右上角，位置随内容长度漂移

### 2. 组件与模块间距
- **[P2]** 主节奏 space-y-6/8 一致但**单调**——无密度变化表达信息重要性；Gemini 视觉评审：Settings「信息密度偏低，需更多滚动」
- **[P3]** 两种容器语言并存：统计格 gap-px 发丝线 vs 其他全部 rounded-xl border 卡片
- **[P3]** 圆角实测三档并存（8/10/14px）+ 药丸（计算值 3.35e7px），无尺度系统

### 3. Markdown 全量渲染（07-wiki-markdown-full）
- ✅ **亮点**：渲染链路完整可靠——标题层级/列表嵌套/表格换行/引用块/行内代码/链接全部正确；Gemini 评审「无明显视觉问题」
- **[P2]** 排版即 `prose prose-sm prose-invert` 默认皮肤，零定制；**正文行长未限**（max-w-6xl 容器内拉满，大屏可读性差）
- **[P3]** mermaid SVG 内嵌字体泄漏：实测 5 处 `trebuchet ms` 16px（WikiGraph/mermaid 未统一 fontFamily）

### 4. Mermaid 渲染
- **[P2]** `theme: 'dark'` 硬编码（WikiMarkdown.tsx:17）——与 `<html class="dark">` 硬编码**侥幸一致**；一旦引入主题切换立即破碎，且无法随主题注入
- **[P3]** 渲染中显示 `<pre>` 原码（无骨架/占位）、错误态裸红字 `mermaid 渲染失败` 无重试

### 5. 图表与 CodeGraph 展示
- **[P1]** WikiGraph **节点无标签**（Gemini：「最核心问题……用户必须靠颜色猜测」）；节点大小固定、边无粗细/方向语义
- **[P2]** 图例静态不可交互（不可点选高亮社区）；无显式缩放/重置控件；「点击节点跳转」提示字号过小
- **[P2]** 12 色社区调色板 + 9 色 TYPE_COLOR 全部硬编码 hex（WikiGraph.tsx:12-29），不随主题
- **[P1·讽刺]** CodeGraph 页 = 表单 + 卡片列表 + `<pre>` 裸文本查询结果——**产品叫 CodeGraph，页面上没有图**

### 6. Settings 配置页（12-settings）
- **[P1]** 表单 5 输入框全部 placeholder 当 label（可用性+无障碍双杀；Gemini 确认）
- **[P2]** 「重加密」作为顶级 tab 与 Providers/路由/API Keys 并列——**危险操作伪装成配置分区**，无警告无确认语境
- **[P3]** 「注册 Provider」按钮视觉权重过低；「删除」按钮不红
- **[P3]** 保存成功/失败无反馈设计（仅错误横幅）

### 7. 其他
- **[P1]** **色彩系统坍塌**（见特异性判定）：品牌蓝 210° 是全应用唯一彩色，占比 0.6%；domain 徽章用 off-token 的 `green-400/purple-400`（暗底低对比）
- **[P1]** **主题架构断裂**：`<html class="dark">` 硬编码（index.html:2）；无切换 UI、不跟随 `prefers-color-scheme`；亮色 token 死码；与「双主题重做」目标正面冲突
- **[P2]** 字号系统：11/12/12.8/14/16/20/24px 七值并存（12.8 为 prose 派生怪值），无 type scale
- **[P2]** 危险操作无确认（会话擦除、provider 删除、wiki source 删除均一键执行）
- **[P3]** StatusBadge pending/running 同色难分；Jobs 错误列 `text-red-400` off-token；登录页脚「Memory · Knowledge · Wiki · CodeGraph」无链接纯装饰

## 亮点（保持）

1. **Markdown 渲染链路**：全要素正确渲染，是全站最可靠的视觉面
2. **StatusBadge 生命周期能见度**：五态徽章全站统一，「异步是常态」原则有基础表达
3. **信息架构**：七域一页、tab 分区、中文导航——骨架无需推翻

## 人物角色红旗

**Alex（急躁重度用户）**：无快捷键、无命令面板（`/` 聚焦搜索都没有）；表格行点击展开详情导致布局跳动；无批量操作（多原子治理要一个个点）。
**Sam（无障碍依赖）**：Settings 表单 placeholder-only 无 `<label>`（屏幕阅读器盲区）；图谱信息 hover-only；状态更新无 aria-live；键盘可达性未验证但焦点环被 border 样式淹没风险高。
**项目 persona：单用户开发者（扫读效率型）**：用量/任务零可视化，趋势靠脑补；蒸馏 L0→L3 管线不可视——「信任源于可溯源」原则在 UI 上无落点；CodeGraph 查询结果无图。
